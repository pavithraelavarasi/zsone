Lesson 01 of 06

Structure, style, behaviour

Every web page is built from three separate ingredients. This lesson shows you what each one does — and why they are kept separate.

One page, three ingredients

In Week 3 you learned that HTML gives a page its skeleton, CSS gives it its appearance, and JavaScript gives it behaviour. Now you are going to learn what that actually means by looking at each ingredient directly.

The separation is not cosmetic. It is deliberate design. Think of building a hospital's information display board:

🏗️
Structure

The board has a heading, department list, room numbers, and a map. The structure describes what is there — not what it looks like.

🎨
Appearance

The heading is large and red. The department names are bold. The map is on the right. Appearance rules are applied to the structure.

⚡
Behaviour

Clicking a department highlights its room. Typing in the search box filters the list. Behaviour is a reaction to user actions.

The key idea — HTML describes what exists and its role. CSS describes how each thing should look. If you remove CSS, the page loses all visual formatting — but the content is still there. If you remove HTML, there is nothing left to style.

Watch the three layers appear — click Reveal

🏗️
HTML — Structure Describes what every piece of content IS: a heading, a paragraph, a link, an image. It has no opinion about colour, size, or font.
🎨
CSS — Appearance Attaches visual rules to HTML elements. "All headings should be dark blue and 28px tall." "All paragraphs should have 16px of space below them." CSS needs HTML to have something to attach to.
⚡
JavaScript — Behaviour Responds to user actions and updates the page without reloading. Used for interactivity, not structure or appearance. This week, you are not reading JavaScript — just HTML and CSS.
This week — you are going to read HTML and CSS directly. Not the JavaScript layer — that comes later. HTML and CSS are human-readable: once you know what the pieces mean, reading them is like reading a well-organised document.
Lesson 02 of 06

Reading HTML tags

HTML is made of tags. Each tag declares the role of a piece of content. Click each tag below to see what it does.

What a tag looks like — without writing code

An HTML tag is a label that wraps around a piece of content. The label says: "this piece of content is a heading," or "this is a paragraph," or "this is an image." You do not need to know how to write tags this week — you need to recognise them when you see them in the DevTools panel.

Every tag has an opening label and a closing label. The content lives between them. Some tags (like images) are self-contained — they carry their own information without wrapping around any text.

What you will see in DevTools — the HTML panel shows every element on the page with its tags, like reading the outline of a document. The tag name tells you the role. Attributes (name="value" pairs after the tag name) tell you extra information about that specific element.

Click each tag to reveal its role

<h1>Heading
The most important heading on the page
The main page heading — there is typically only one. Tells the browser (and search engines) what the page is primarily about. h1 through h6 form a hierarchy of headings, h1 being most important.
<h2> <h3>Heading
Section and sub-section headings
Secondary and tertiary headings — used to break the page into sections and sub-sections. Like chapters and sub-chapters in a book. You will see multiple h2s and h3s on a single page.
<p>Text
A paragraph of text
Contains a block of body text — a paragraph. The browser adds space above and below it by default. If you see a block of reading text on a page, it is almost certainly inside a p tag.
<a>Link
A clickable link to another page or section
Creates a hyperlink. The href attribute (short for "hypertext reference") holds the destination URL. In DevTools you can see exactly where every link points by reading its href value.
<img>Media
An image embedded in the page
Places an image. The src attribute tells the browser where the image file is. The alt attribute is a text description for screen readers and for when the image cannot load. This tag has no closing tag — it is self-contained.
<ul> <li>List
An unordered list with items
ul is the list container (unordered = bullet points). Each item in the list is inside an li tag. Navigation menus on most websites are actually a ul with li items inside — even though they look nothing like a bullet list once CSS is applied.
<div>Container
A generic container — the most common tag
A box that groups other elements together, with no inherent meaning of its own. Used extensively for layout. In DevTools you will see hundreds of div tags — they are the structural boxes that CSS then sizes, colours, and positions.
<header>Landmark
The page's top section
Contains introductory content — typically the logo, site name, and navigation. Tells browsers and assistive tools "this is the header of the page." Functionally similar to div, but with a meaningful role.
<nav>Landmark
Navigation links section
Contains the main navigation links. Marks a section of the page as navigational. Usually contains a ul with li and a elements inside. Despite containing a list, CSS typically makes it look like a horizontal menu bar.
<main>Landmark
The main content of the page
Wraps the dominant content of the page. There should only be one main per page. Everything in here is the actual content a user came for — not navigation, not footer, not sidebar. Look for this tag to find the important content fast.
<footer>Landmark
The bottom section of the page
Contains closing content: copyright, additional links, contact details. Comes at the end of the page's HTML structure. In DevTools you can scroll to the bottom of the HTML tree to find it.
<span>Inline
An inline container for text styling
Like a div but for wrapping a small piece of text inline — to apply CSS to a single word or phrase within a paragraph. On its own it has no visible effect; its purpose is to give CSS something to target.
Nesting — Tags live inside other tags. A nav contains a ul which contains li elements which contain a tags. The DevTools panel shows this as an indented tree. The deeper the indent, the more deeply nested the element. When you map a page's structure, you are describing this nesting.
Lesson 03 of 06

CSS is appearance

CSS is the layer that makes a page look the way it looks. Without it, all pages look the same — just text and images with browser defaults.

How CSS connects to HTML

CSS works by targeting HTML elements and applying visual rules to them. Think of it as a stylesheet that says: "find every heading on this page, and make it 28px, dark blue, and bold." The heading's content is still in the HTML — CSS only changes how it looks.

The targeting mechanism (called a selector) can point to a tag type ("all h1 elements"), or to a specific element by its id or class attribute. When you see a class or id attribute in DevTools, that is the hook CSS uses to target that specific element.

Key insight — CSS does not exist without HTML to attach to. And HTML without CSS still shows all its content — just without any visual design. The separation means a developer can completely redesign a page's look without touching the content at all.

CSS in DevTools — where it lives

When you select an element in the HTML panel, the Styles panel shows you every CSS rule applied to that element. You see the property, its value, and which stylesheet it came from. Some properties come from the page's own CSS. Some come from the browser's default stylesheet. You can see them all.

What you see in Styles panelWhat it means
font-size: 28pxThe text in this element is 28 pixels tall
color: #1e3a5fThe text colour is a dark navy blue (hex code)
margin-bottom: 16pxThere are 16 pixels of space below this element
background-color: #f0f7ffThe element has a light blue background
border-radius: 8pxThe corners of this element are rounded by 8 pixels
You do not need to memorise all CSS properties — you need to be able to read them. A property name like font-size, background-color, or border-radius describes exactly what it controls. Read the name, read the value, describe the visual effect. That is the skill this week.
Lesson 04 of 06

Reading CSS properties

Practice connecting CSS property names and values to the visual effects they produce. This is the core reading skill for your assignment.

The reading pattern

Every CSS rule in the Styles panel follows the same pattern: a property name, a colon, and a value. To read it correctly, ask: what does this property control visually, and what does this specific value produce?

For example: font-weight: 700 — the property is font-weight (how bold the text is), the value is 700 (bold — the scale runs 100 to 900). Plain English: the text is rendered bold.

The DevTools inspector

Your browser has a built-in tool that lets you see the HTML and CSS of any page. Click the rows below to explore a mock DevTools panel.

What DevTools shows you

The developer tools in your browser contain an inspector: a panel split into two sides. The left side shows the live HTML structure of the page — every element, nested exactly as the browser has built it. The right side shows the CSS styles applied to whichever element you have selected on the left.

These two panels are connected. Click an element in the HTML panel — the styles panel immediately updates to show that element's CSS.

How to open it — there is a keyboard shortcut and a right-click menu option. Research "how to open browser developer tools" to find both. The panel can be docked to the bottom, side, or a separate window. Find what works for your screen size.

What the Styles panel shows — every CSS property currently applied to the selected element, its value, and where the rule comes from. Properties crossed out in the panel have been overridden by a more specific rule — this is how you find conflicts between CSS rules.

Navigating to a specific element

You do not have to scroll through the entire HTML tree to find an element. There is a way to right-click directly on the thing you see on the page and jump straight to it in the panel. Research the term "inspect element" to find it.

What "live" means — the DevTools panel shows the live DOM — what the browser has built in memory after processing the HTML and running any JavaScript. If the page updates after you load it (a notification appears, a counter changes), the panel updates too. You are seeing the page as it is right now, not as it was when it was written.
Lesson 06 of 06

Reading a page's structure

Now you put it together — HTML tags, CSS properties, and DevTools — to read an unfamiliar page from the top down.

How to approach an unfamiliar page

When you open the HTML panel on a page you have never seen before, resist the urge to read every detail immediately. Start with the big picture. The HTML tree always goes from outermost to innermost. Start at the top of the tree and work down: identify the major sections first, then zoom into specific elements.

🗺️
Step 1: Major sections

Find the header, main content area, and footer. These are the top-level containers.

🔍
Step 2: Key elements

Inside main content, find headings, paragraphs, images, and links.

🎨
Step 3: Styles

Click specific elements to read their CSS. Connect property names to visual effects.
