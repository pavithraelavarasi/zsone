Lesson 01 of 06

The shell is just a language

Your terminal is not a different computer. It is a different way of talking to the same computer you already use.

You have already used a shell

In Week 1, you connected to a remote server by typing a command. In Week 3, you used the terminal to check whether a server was alive and to make HTTP requests. You were not programming — you were speaking to the operating system in its native language.

That language is the shell. It is a text interface between you and the operating system. Instead of clicking icons and dragging windows, you type an instruction, press Enter, and the OS carries it out. It prints the result directly back to you.

The key idea — everything you do with a mouse and a GUI — open a folder, rename a file, copy something — is also expressible as a text command. The GUI is a visual layer built on top of the same underlying operations the shell exposes directly.

Why bother with text commands? A GUI requires a screen and a mouse. A shell works with just a keyboard — over a network, on a remote machine, inside an automated script, or on a server with no screen at all. Every server you will ever work with as a developer has a shell. Almost none have a GUI.
Lesson 02 of 06

The filesystem is a tree

Every file on every computer lives at a specific address in a branching structure. Understanding that structure is what makes navigation possible.

Think of a library's organisation

A library does not scatter books randomly. It has a building, inside the building are sections, inside each section are shelves, and on each shelf are books. Any book can be found by following the path: Building → Section → Shelf → Book.

A computer filesystem works exactly the same way. Everything lives at a specific address — a path. To reach any file, you follow the branches of the tree from the root down to that file.

One key difference — a library has one building with multiple entrances. A filesystem has one root. Everything on the entire system — every directory, every file — branches from a single starting point written as just /. The first slash in any path always means "start at the root."

Three things to know

📁
Directory

A container that holds files or other directories. The shell word for "folder." Directories can nest as deep as needed.

📄
File

Actual data — text, logs, config, images, code. Always lives inside a directory. Cannot exist between directories.

/
Root

The single top of the tree. Every path starts here. Written as a forward slash on its own.

A path is a complete address — /home/librarian/reports/jan_2025.txt means: start at root, go into home, then librarian, then reports, and there you will find the file. Each / is a level separator — the same role as City / Street / Building / Flat in a postal address.
Lesson 03 of 06

Location and paths

In the shell you are always somewhere specific. Understanding where you are — and how to describe anywhere else — is the foundation of everything.

The shell always has a current location

Unlike a file browser where you can see the whole tree at once, the shell is like being physically inside one directory at a time. You can look around, move, and do work — but only relative to your current position.

There is a command whose entire job is to tell you where you are right now. It prints the complete path from the root to your current directory. Developers run it constantly to orient themselves — especially on unfamiliar servers. Think of it as asking your GPS: "where am I?"

What the output looks like — a path starting with /, such as /home/librarian. Read it left to right: root → home → librarian. You are inside the librarian directory, which is inside the home directory, which is at the root of the system.

The home directory shortcut

Every user on a Linux system has a personal directory — their home directory — at /home/[username]. This is where you land when you first connect via SSH.

The shell has a shortcut symbol for "my home directory": the tilde character ~. Wherever you are in the filesystem, this symbol always means your own home directory. Typing it as a destination takes you home instantly — developers use it constantly.

A common mistake — confusing absolute and relative paths. An absolute path always starts with /. A relative path never starts with /. If a command fails and the path looks correct, the first thing to check is whether you used the right type for where you currently are.
Lesson 04 of 06

Listing and reading

Two of the most-used shell operations: seeing what is in a directory, and seeing what is inside a file — both without any application.

The listing command — what is in this directory?

The listing command prints the contents of your current directory as text. By default you get just the names. With additional options you can also see file sizes, modification dates, permissions, and a clear marker distinguishing files from directories.

Toggle between simple and detailed output — same command, different options
reports/   notes.txt   schedule.csv   config.conf
total 48 drwxr-xr-x  2 librarian  staff  64 Jun 10 09:14  reports/ -rw-r--r--  1 librarian  staff  412 Jun  9 14:22  notes.txt -rw-r--r--  1 librarian  staff  1.2K Jun 11 00:03  schedule.csv -rw-r--r--  1 librarian  staff  88 May 31 16:45  config.conf
Simple output: just names. Directories end with / so you can tell them from files at a glance.

The read command — what is inside this file?

The read command prints the entire content of a file in the terminal. The file does not open in any application — its text simply appears in the terminal output below your command. This is how developers inspect configuration files, log files, and data files on a remote server with no GUI.

When files are long

A log file can have thousands of lines. Printing all of them fills your terminal and scrolls past before you can read anything. The shell has dedicated tools for this situation:

📖
Page-by-page reader

Shows one screenful at a time. You press a key to advance, and another to quit. Nothing scrolls out of view.

⬆️
First lines only

Shows the first N lines of a file — useful for reading a file's header or confirming what type of data it contains.

⬇️
Last lines only

Shows the last N lines — ideal for log files, where the most recent events are always at the bottom.

Why the last-lines command matters for logs — a system log that has been running for months starts with events from months ago. When something just broke, you need the most recent lines, not the oldest. The last-lines command jumps you directly to the bottom of any file.

Navigation and movement

Moving between directories, creating structure, and organising files — without touching a mouse.

Changing your current location

The navigation command moves you to a different directory. You give it a destination as either an absolute or relative path, and your current location changes instantly. After running it, the path you see in your prompt updates — you are now somewhere else in the tree.

Creating and organising

Beyond navigation, the shell lets you build structure — create directories, create files, copy them, and move them — all from text commands.

📁 ➕
Create directory

A command that makes a new empty directory at the path you specify — like New Folder in a GUI file browser.

📄 ➕
Create empty file

A command that creates an empty file at a path. Also used to update a file's timestamp without changing its contents.

📋
Copy

Copies a file to a new path. The original stays. You give it a source and a destination.

✂️
Move / Rename

Moves a file to a new path or renames it. Unlike copy, the file is no longer at the original path after the command runs.

The shell has no undo — when you move or delete a file in the terminal, there is no Ctrl+Z, no Recycle Bin. On a remote server it is often gone permanently. This is why developers read their command carefully before pressing Enter — especially for anything that modifies or removes files.
Lesson 06 of 06

Remote shells and SSH

The shell is not limited to your own machine. SSH gives you a shell on a computer anywhere in the world — and you use the exact same commands.

You have already done this

In Week 1 you connected to the course server via SSH and uploaded files via SCP. At the time the focus was on using those tools to submit work. Now that you understand what a shell is, you can see what was actually happening.

When you connected via SSH, the server opened a shell session and handed it to you. From that point, every command you typed — every navigation, every listing, every file read — ran on the remote server. The filesystem you were browsing belonged to a machine somewhere on the internet, not your laptop.

The remarkable thing — the commands are identical. The navigation command works the same on your laptop, on the course server, on a cloud machine, on a production server. Once you learn the shell, you can work on any Linux machine in the world. The interface is portable.

What happens when you connect — step by step

1
You run the SSH command with the server address and your username Your terminal initiates a secure encrypted connection across the network to the server.
2
The server verifies your identity Authentication — password or key-based. The server confirms you are allowed in before opening anything.
3
The server opens a shell session and drops you into your home directory Your prompt changes to show the server's name. Everything from here runs on the remote machine.
4
Every command you type executes on the remote server The listing command shows the server's directories. The path command shows your location on the server's filesystem — not your laptop's.
5
When you disconnect, the session ends — your files remain The shell closes. Your terminal returns to your local machine. Everything you created or modified on the server stays there.

SSH vs SCP — the same secure connection, different purposes

SSH — interactive session

Opens a live shell on the remote machine. You type commands, they run remotely, you see the output. The connection stays open until you close it. Used for exploration, administration, running programs.

SCP — file transfer

Copies a specific file between machines over the same secure connection. You give it a source path and a destination path. It connects, transfers the file, and disconnects. No interactive shell — just the transfer.

You now understand the full picture — what the shell is, how the filesystem tree is organised, how to find your location in it, how to navigate and read files, and how SSH gives you a shell on a machine anywhere in the world. Every time you submit work to the course server from here, you will understand exactly what is happening at each step.
